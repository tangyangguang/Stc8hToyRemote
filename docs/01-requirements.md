# 需求说明

## 项目目标

本项目重写 STC8H1K08 玩具遥控器 controller 和接收机 receiver 固件。目标是在保留既有硬件和用户可观察行为的基础上，使用 `../Stc8hBase` 重新实现清晰、可验证、可维护的双板遥控系统。

## Legacy 边界

`legacy/old-prj/` 只作为需求线索来源：

- 可以提取硬件接线、控制输入、执行输出、用户交互和异常场景。
- 每条需求都要重新评估，不默认继承旧实现。
- 禁止复用旧代码结构、旧协议流程、旧函数、旧全局缓冲区、旧 nRF24L01 实现和旧 EEPROM 布局。

旧实现中不合理的做法不迁移。本固件不做旧 API 兼容层。

## Controller 需求

- 读取方向、速度、刹车、转向、灯、蜂鸣器、Fn 和 EC11 中键输入。
- EC11 旋转控制速度 `0..100`；正常模式可快转加速，配置模式禁用加速。
- EC11 中键短按为刹车并清零速度；长按进入配置模式；在 `Lxxx` 丢链状态下双击启动手动扫频。
- 支持舵机反向、方向反向、中位微调、中位虚位和端点收缩配置，并保存到 EEPROM。
- 舵机最小更新步进通过 `APP_STEERING_MIN_STEP_DEGREES` 编译期宏配置，默认 1 度。
- 上电优先使用保存频道，默认频道为 `76`。
- 连不上保存频道时显示 `Lxxx`，锁定该频道重试，不自动扫频。
- 正常控制时约 20ms 发送一次最新控制状态，不排队重发过期控制包。
- 显示连接状态、速度、方向、刹车、配置项、本机电压和接收端回传电压。
- nRF24 初始化失败时显示明确错误码，避免误判为普通丢链。

## Receiver 需求

- 接收并验证 controller 控制 payload。
- 未绑定时绑定第一个合法非零 `tx_id`；已绑定后只接受相同 `tx_id`。
- 驱动 AT8236 电机、舵机、灯、蜂鸣器和辅助 PWM。
- AT8236 与辅助 PWM 共用 PWM-B，默认约 20.03kHz；频率通过 `APP_OUTPUT_FAST_PWM_PRESCALER` / `APP_OUTPUT_FAST_PWM_PERIOD` 编译期宏配置。
- 电机最低有效 PWM 占空比可通过 `APP_OUTPUT_MOTOR_MIN_DUTY_PERCENT` 编译期宏配置，默认 35%。
- 回传链路状态和电池电压；电池电压平时后台低频采样，controller 请求时提升采样频率。
- 掉线或射频错误时进入安全状态：
  - AT8236 IN1/IN2 duty 为 0。
  - 舵机保持最后输出角度，不强制回中。
  - 灯关闭。
  - 蜂鸣器关闭。
  - 辅助 PWM 关闭。
- receiver LED 高电平亮，用不同闪法表示启动、射频错误、等待、连接和清除绑定。

## 频道和绑定

- 默认频道为 `76`，controller 和 receiver 的全新默认配置必须一致。
- receiver 默认构建启用 P30/P31 运行期频道维护键，用于多套遥控器/接收机同时使用时避开同频道冲突。
- P30/P31 低电平有效，receiver 固件必须显式启用 P3.0/P3.1 数字输入和内部上拉；没有外部上拉电阻时仍应能正常读取释放态。
- 运行期只接受稳定约 30ms 的单键按下边沿；按住不连续重复切换，释放也需稳定后才允许下一次单键切换。
- 运行期双键同时按下不切频道，必须全部释放后才允许下一次单键切换。
- P30/P31 在预设频道池中切换并保存：`76,72,68,64,60,56,52,48,44,40,36,32,28,24,20,16`。
- receiver 读取 EEPROM 时只接受预设频道池内的 `rf_channel`；池外值恢复为默认频道 `76` 并保留已有绑定信息。
- 切换频道后必须重新设置 nRF24 RX 频道、flush RX、清 IRQ、回到 RX，输出进入安全态，LED 进入等待/未连接状态，并重新预装 ACK payload。
- receiver 默认保留 P30+P31 上电同时按下清绑定入口；清绑定只清 `bound_tx_id`，不改变保存频道。
- 已连接状态下不实现协商换频；本机切换频道按丢链/维护处理，controller 显示 `Lxxx` 后可用既有交互手动扫描恢复。

## 非目标

- 不做旧项目 API、无线格式或 EEPROM 布局兼容。
- 不做加密、mesh、路由或跳频扩频。
- 不做一只 controller 同时可靠控制多只 receiver；该能力需要单独设计无 ACK 或轮询协议。
- 不在应用项目中复制基础库驱动代码。
