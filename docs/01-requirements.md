# 需求说明

## 项目目标

本项目重写 STC8H 玩具遥控器 controller 和接收机 receiver 固件。目标不是迁移旧实现，而是从旧项目提取真实业务需求，评估合理性后，在当前项目和 `../Stc8hBase` 基础上独立设计。

## Legacy 边界

`legacy/old-prj/` 只作为需求线索来源：

- 可以提取硬件接线线索、控制输入、执行输出、用户可观察行为、异常场景。
- 必须重新评估每条需求是否合理。
- 禁止参考旧代码结构、旧协议流程、旧函数、旧全局缓冲区、旧 nRF24L01 实现和旧 EEPROM 布局。

旧实现中不合理的做法不迁移。新项目不做旧 API 兼容层。

Tx V2.x 记录文件的需求评估见 [Tx V2.x 记录需求评估](07-tx-v2-notes-assessment.md)。

## controller 需求

- 读取方向、速度、刹车、转向角度、灯、蜂鸣器、辅助 PWM、状态/电压请求。
- 刹车需求至少包含“刹车并清速度”和“刹车但不清速度”两种线索，业务迁移前需要确认最终交互。
- 周期发送最新控制状态；遥控类业务不排队重发过期控制包。
- 支持手动频道扫描，避免多个遥控器/接收机同时使用时只能固定在同一频道；上电连不上时不自动扫描，只有显示 `Lxxx` 后 EC11 中键双击才启动扫描。
- 遥控器保存 `APP_TX_ID`、手动扫描成功频道和校准配置；后续优先从保存频道启动。
- 默认频道使用 `76`；controller 和 receiver 的全新默认配置必须一致。
- 支持 EC11 中键长按进入配置模式，保存方向反向、舵机反向、舵机中位和舵机端点收缩。
- 显示必要运行状态，例如速度、方向、连接状态、电池电压或错误状态。
- 通信失败时给出可观察状态，避免用户误以为接收机仍受控。
- 电池供电下限制无线发送频率、显示刷新、ADC 采样和阻塞等待。

## receiver 需求

- 接收并验证 controller 控制 payload。
- 输出执行器状态：电机、舵机、灯、蜂鸣器和辅助 PWM。
- 定期或按请求回传状态，例如链路状态和电池电压。
- 支持接收机本机频道调整和持久化，便于多台玩具错开频道使用。
- 接收机本机频道调整优先在预设频道池内切换；连接状态下改频道应走协商换频，不能直接切走导致 controller 丢链。
- 未绑定接收机接收第一个合法非零 `tx_id` 后绑定并保存；已绑定接收机只接受相同 `tx_id`。
- 超过业务包超时时间后立即进入安全状态：
  - 电机速度为 0，驱动进入停止或明确刹车/滑行策略。
  - 灯关闭。
  - 蜂鸣器关闭。
  - 辅助 PWM 关闭。
  - 舵机回中。
- 电池供电下减少无意义 PWM 输出、ADC 采样和状态回传；断联等待时降低无线和外设活动频率。

## 非目标

- 当前不做加密、mesh、路由或多节点调度。
- 当前不做旧项目 API 兼容。
- 当前不做跳频扩频；多车同时使用通过“不同频道 + 必要时不同 `APP_TX_ID`”解决。
- 多只遥控器需要用编译期 `APP_TX_ID` 区分，或给接收机设置不同频道。
- 当前不做“一只遥控器同时控制多只接收机”；该能力后续需要单独设计组播/无 ACK 或轮询控制协议。
