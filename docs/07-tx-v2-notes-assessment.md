# Tx V2.x 记录需求评估

## 来源

资料：

```text
legacy/old-prj/Tx遥控器端V2.x功能说明.txt
```

该文件记录 Tx 遥控端 V2.0 到 V2.3 的功能线索。它可能与旧代码不完全一致，只作为需求线索，不作为实现参考。

## 可确认的需求线索

### 通道和输入

- 马达方向：前进/后退。
- 马达速度：`0..100`。
- 刹车：至少存在两类语义：
  - EC11 中键：刹车并速度置 0。
  - 独立刹车键：按下刹车，不清零原速度，松开后恢复原速度。
- 转向：10K 电位器映射到舵机 `0..180`，中值约 `90`。
- 灯光：开关量。
- 喇叭：开关量。
- 辅助 PWM/MOS：`0..100`，但在后续记录和旧 Tx 代码中多次被注释；旧 PCB 是否实际接出第二个电位器需要实测或查板。
- Fn 按键：请求/显示电池电压。

### 显示

- 4 位 TM1637 数码管用于显示方向、速度、辅助 PWM 比例和通信失败状态。
- 记录中提到通信失败时显示冒号；新项目可以保留“通信状态可观察”的需求，但不要求复刻具体显示形态。

### 配置模式

记录中提到配置模式：

- 舵机反向。
- 舵机中值。
- 舵机减少角度。
- 方向是否反转。
- 配置保存到 EEPROM。

这类需求涉及持久化和校准，必须单独设计版本、长度、CRC、默认值和恢复路径后再实施。

### 硬件线索

- nRF24L01 IRQ 后续调整到 P32。
- TM1637 曾调整到 CLK P34、DIO P31。
- 独立刹车按钮曾调整到 P30。

这些只能作为引脚线索。最终引脚以新项目 `board_pins.h` 和硬件实测为准。

## 需求评估结论

### 保留为当前核心需求

- 方向、速度、刹车、转向、灯光、喇叭、电压请求。
- 通信失败必须可观察。
- receiver 掉线必须进入安全状态。
- 电池供电下要限制无线、显示、ADC、PWM 的无效活动。

### 保留但重新设计

- 辅助 PWM：保留协议字段，receiver 已实现 MOS PWM 输出和安全态关闭；controller 端目前没有可确认的第二电位器 ADC 引脚，默认发送 `0`，避免误驱动。
- 两类刹车：在 controller 侧归约为 `TOY_REMOTE_BRAKE_HOLD_SPEED` 和 `TOY_REMOTE_BRAKE_CLEAR_SPEED`，无线 payload 仍只发送 `brake` 和 `speed`。
- 配置模式：保留为后续需求，不在阶段 3 前实现。
- 电池电压：保留为状态回传和显示需求；采样和显示必须限频。
- TM1637 显示：保留“状态显示”需求，不复刻旧显示编码。
- 转向电位器：保留线性 `0..1023` 到 `0..180` 的归约；中值校准、死区和端点减少角度属于后续配置模式。

### 修正旧记录中的设计

- 旧记录中的无线 payload 没有版本字节；新协议必须包含 `version`。
- 旧记录直接描述 nRF24 业务数据格式；新项目业务 payload 必须放在 `proto_rf_link` payload 内。
- EEPROM 保存配置不能直接复用旧地址或布局。
- 旧“按键组合进入配置模式”需要重新评估误触风险和可用性。

### 暂缓

- 频道扫描和绑定。
- 持久化配置。
- 方向/舵机校准 UI。
- controller 端辅助 PWM/MOS 输入。

## 对当前协议的影响

当前 `shared/toy_remote_protocol` 的控制 payload 已覆盖这些核心字段：

```text
version
direction
speed
brake
steering_angle
light
buzzer
aux_pwm
request_voltage
```

与记录文件相比，新协议增加 `version`，并把字段范围校验放入 `shared/`。这是合理修正，不是兼容旧格式。

## 待确认问题

- 旧 controller PCB 是否实际接出辅助 PWM/MOS 电位器；如果有，需要确认 ADC 通道/引脚。
- 独立刹车键是否需要“刹车但不清速度”的恢复语义。
- EC11 中键是否继续作为“刹车并清速度”。
- 配置模式是否仍需要通过按键组合进入，还是改为更明确的设置流程。
- receiver 电池电压和 controller 自身电池电压是否都需要显示。
