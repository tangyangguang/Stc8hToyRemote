# 频道策略与多车边界设计

## 目标

本设计覆盖默认频道、接收端频道键、多车同时使用、连接中换频和一遥控多接收边界。目标是在不增加硬件的前提下，让多台玩具能较容易错开频道，同时避免日常使用中误切频道导致遥控器丢链。

## 默认频道

默认频道设为 `76`。nRF24L01 的频道号对应中心频点 `2400 + RF_CH MHz`，频道 `76` 对应 2476MHz，比旧默认 `40` 更远离常见 2.4GHz Wi-Fi 信道 6 的中心区域，也不贴近频段上边缘。controller 和 receiver 的全新默认配置必须一致。

已有 EEPROM 配置不会因为默认值变更自动改到 `76`。只有配置无效、首次初始化、清除配置或后续明确迁移时才使用默认频道。

## 预设频道池

receiver 的 P30/P31 频道键用于多接收机部署和维护，不作为日常连接步骤。频道键不在 `0..125` 上逐步遍历，而是在预设频道池中切换：

```text
76, 72, 68, 64, 60, 56, 52, 48,
44, 40, 36, 32, 28, 24, 20, 16
```

该频道池用 4MHz 间隔降低同场多车的相邻频道干扰。默认从 `76` 开始；多台 receiver 依次取前面的预设频道。8 台以内是推荐目标；8 到 16 台需要现场验证；16 台以上需要正式规划频道、RF 地址、发送频率和现场测试，不再靠简单按键配置承诺稳定。

## 未连接状态下调频道

receiver 未连接时，P30/P31 可以立即切到上一个或下一个预设频道，保存配置，进入安全输出，并用 LED 给出确认反馈。controller 不自动扫描；用户需要在 `Lxxx` 状态下双击 EC11 中键启动扫描，扫到后显示 `Fxxx` 并保存频道。

## 已连接状态下协商换频

receiver 已连接时，P30/P31 不能立即切换 nRF24 频道。直接切走会让 controller 留在旧频道并进入丢链。目标流程是协商换频：

```text
receiver P30/P31 短按
  -> 计算目标预设频道 pending_channel
  -> 继续留在旧频道，通过 ACK 状态上报 pending_channel
controller 收到 pending_channel
  -> 显示 Hxxx
  -> 在旧频道发送确认换频命令
receiver 收到确认
  -> 保存新频道并切到新频道
controller 随后切到新频道
  -> 收到有效 STATUS ACK 后显示 Fxxx
  -> 回到正常控制界面
超时或新频道确认失败
  -> 双方回退旧频道，或 controller 进入 Lxxx 锁定重试
```

`Hxxx` 表示正在协商切换到频道 `xxx`。该流程要求状态 payload 增加待切频道字段，控制 payload 增加换频确认命令，或等价新增极小配置命令包。具体字段在实现前再进入协议变更设计，不能偷用现有业务字段。

当前 8KB 固件版本暂不实现该协议扩展。2026-05-19 本轮生命周期实现后 controller 为 `8105/8192` bytes，仅剩 `87` bytes，不适合继续塞入双端协商换频状态机。当前已落地能力是未连接维护场景下的预设频道切换，以及 controller 在 `Lxxx` 下双击手动扫描恢复。

## 多接收机边界

当前主线是一只 controller 控制一只 receiver。一遥控多接收暂不实现。

老项目固定 RF 地址和频道，可能出现“同地址同频道的多个 receiver 都执行同一控制”的效果，但它不是严格可靠的一遥控多接收设计。多个 receiver 同时自动 ACK 会互相冲突，ACK 状态回传也无法区分来源。

后续若要做一遥控多接收，应独立设计：

- 同步组播：同频道同组 ID，关闭 ACK 或使用无 ACK 控制包，多只 receiver 同步执行同一动作，但不保证逐台状态回传。
- 逐台控制：controller 保存 receiver 列表，按 receiver_id 轮询发包和收 ACK，适合少量接收机，数量增加会带来控制延迟。

当前多车一起玩使用多套 controller/receiver，通过不同预设频道、必要时不同 RF 地址和不同 `APP_TX_ID` 避免冲突。

## 验证标准

- 全新 controller 和 receiver 默认频道均为 `76`。
- receiver P30/P31 在预设频道池内循环切换并保存。
- 未连接状态调频道后，controller 只有在 `Lxxx` 下双击扫描才找到新频道。
- 已连接状态协商换频为后续验证项；当前版本若误切 receiver 频道，应按丢链处理，controller 显示 `Lxxx` 后手动扫描恢复。
- 多接收机部署测试至少覆盖 4 台；若目标超过 8 台，需要记录现场 Wi-Fi/蓝牙环境和每台频道分配。
- 当前不测试一遥控多接收；该能力不属于本阶段交付。
